Spacing scale

An 8px-based magazine scale, --sp-1 through --sp-8. Works well as a base — the issue is it's under-used: many gaps and paddings in home-v2.css are still raw px values (14px, 22px, 32px…) that don't map to the scale.

--sp-3 24px
--sp-4 36px
--sp-5 56px
--sp-6 80px
--sp-7 112px
--sp-8 160px

Section rhythm

After the audit fixes, "normal" sections (brands, difference) use a single symmetric formula: padding: clamp(96px, 12vh, 144px) 0. Inventory keeps a header-offset top. Sell & Services are sticky scroll-runways (200vh / 130vh) — deliberate exceptions, not part of the rhythm. This should become a --section-py token — the current --section-py: 140px is declared but barely referenced.

Section junctions — stacked-page rule

For stacked content pages (SRP / inventory), every gap between two consecutive sections — the junction — is a single value: --sp-5 (56px). One scale step, used everywhere. No raw px, no exceptions.

  • Top-ownership. Each section owns its leading gap: padding-top: var(--sp-5), padding-bottom: 0. Adjacent sections never both contribute — so every junction is exactly one --sp-5, never a sum of two paddings.
  • Borders hug content. A section's own bottom hairline sits flush against its content (padding-bottom: 0); the 56px lives after the rule, owned by the next section.
  • Internal insets ≠ junctions. Padding inside a component (e.g. the filter-bar's row-to-border inset) is not a junction — it uses a smaller step (--sp-3) and is exempt from the 56px rule.
  /* every section, stacked page */
  padding: var(--sp-5) 0 0;   /* 56 top · 0 bottom → junction = 56 */

05 — Foundations

Radius, elevation & motion

The system is intentionally flat by default. Border-radius lives on a small scale. Elevation is reserved — only catalog cards (.vehicle-card--extended) lift on hover; everything else stays flat. Motion is a single soft easing curve applied consistently.

Radius

0pxBoutique CTAs — sharp editorial corners.
5pxVehicle-card media, service cards.
6pxReview cards. (Why not 5? — drift.)
999pxPill CTAs, social chips, status dot.

Recommend collapsing to a 3-step scale: --r-sharp: 0 · --r-card: 5px · --r-pill: 999px. The 6px review-card is the only outlier.

Elevation — flat by default, one exception

No drop shadows on cards, panels, header, or modals. The single elevation in the system is the catalog-card hover-lift on .vehicle-card--extended (SRP).

--card-lift 0 24px 56px -20px rgba(28,28,28,0.18) Diffused, low-alpha shadow that suggests gentle elevation. Used only on .vehicle-card--extended:hover together with transform: translateY(-4px).

Rule: if a new component needs elevation, reuse --card-lift. Don't invent new shadows. The page stays editorial-flat; lift signals "catalog item, clickable."

Motion — one easing, two durations

All transitions use a soft ease-out curve so movement decelerates gently into rest — never snaps. Durations are short for state changes (hover, fade), longer for hover-lifts and reveals.

--card-ease cubic-bezier(0.16, 1, 0.3, 1) Ease-out-expo. The default. Used for hover-lift, reveals, panel slides. Gentle landing — no snap.
--ease cubic-bezier(0.22, 1, 0.36, 1) Ease-out-quint. Faster start than --card-ease, similar tail. Used for small state changes (button hover color, dropdown toggle).
--card-dur 0.6 s Hover-lift, panel slides, photo zoom — anything that should feel "considered, not snappy."
short 0.25 – 0.35 s Hover color shifts, dropdown open/close, caret rotation, simple opacity fades.

Rule: every new transition uses var(--card-ease) for movement / depth, or var(--ease) for simple state. Duration: 0.6 s for lifts & reveals, 0.25–0.35 s for state. Never invent a new bezier — if you reach for one, the design system is wrong somewhere.

09 — Audit

Inconsistencies found

What's currently fighting the system. None of these are broken — they're drift. Each one is a candidate to become a single reusable rule.

01

Two sources of truth for type

home-v2.css declares --font-display: Antic Didone + --font-serif: Playfair. index_4.html overrides all three font tokens to Plus Jakarta Sans / Inter via a ~400-line inline <style> block. The CSS file's tokens no longer describe the live site.

High
02

Heading sizes — fixed in the patch layer, not the source

Six sections originally had six different primary/secondary size pairs. The inline block unified them to one pair — but home-v2.css still carries the old varied values (.sell__heading-primary: 50px, .events__heading-primary: clamp(30,3vw,42), etc.). The override wins, but the file lies.

High
03

Section backgrounds not tokenized

Sell uses #d4d4d4, events #cfcfcf, services a #fff → #d4d4d4 radial, the services media placeholder #a8a8a8. None map to --bg / --bg-soft / --bg-deep. ~5 hard-coded grays.

Medium
04

CTA pattern copied 5+ times

.inventory__cta, .sell__cta, .services__cta, .services__cta--ghost, .diff__cta, .diff__cta--ghost each re-declare the same slide-fill button from scratch. One .btn + modifiers would replace ~150 lines.

High
05

Border-radius has no scale

0 / 5px / 6px / 999px / 50% in use. The 6px review-card vs 5px everywhere-else is pure drift.

Low
06

Body / intro font-size drift

Intros ranged 13.5 / 14 / 14.5 / 15 / 15.5px across sections. The inline block normalized most to 15px — but home-v2.css still has the originals (.events__intro-text: 13.5px, .diff__para: 15.5px).

Medium
07

Six responsive breakpoints, no system

Media queries fire at 1100 / 960 / 880 / 720 / 600 / 560px — picked per-component, never standardized. Should collapse to ~3 (e.g. 1100 / 760 / 540).

Medium
08

Spacing scale under-used

--sp-* exists but raw values (14px, 22px, 20px, 32px gaps) are scattered through home-v2.css. --section-py is declared but barely referenced.

Low
09

Dead / orphan CSS

.section--diff-v1 + .diff-v1__* and .section--diff-v2 + .diff-v2__* — explicitly commented "ORPHAN … safe to delete", ~700 lines, zero HTML references. Also .section--inventory__sticky ("sticky removed") and the .display class are leftovers.

Dead
10

The inline patch layer itself

index_4's ~400-line inline <style> is doing real system work (type ramp, audit fixes, brand logos). It's fine as a staging area — but it means every future page needs the same patch, or it must be merged into a proper stylesheet.

High
